# Security policy

## Supported versions

Before the first stable release, security fixes are made on the default branch.
After releases begin, this file will list the supported release lines and dates.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's
private GitHub Security Advisory reporting flow when the public repository is
available. Until then, contact the project maintainers through a private channel
identified in the repository profile.

Include the affected version/commit, impact, reproduction steps and any proposed
mitigation. Do not include real tenant data or secrets. Maintainers will
acknowledge the report, coordinate validation and remediation, and credit the
reporter if requested and appropriate.

The project does not offer a bug bounty or contractual response-time guarantee.
